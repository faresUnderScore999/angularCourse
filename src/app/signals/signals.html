What is a Signal?

A signal is a small container for a value that can change over time. Code can read the value and react to it automatically — whenever a signal changes, every computation that depends on it updates itself. Introduced in Angular 17, signals are now the change-detection primitive at the heart of Angular.

Signals vs. a plain variable

What you want Plain value Angular signal
Store the state let count = 0; const count = signal(0);
Read the value count count()
Write a new value count = 5; count.set(5);
Learn that it changed You check manually Dependents re-run automatically
Update the view Manual bookkeeping Only the parts that read it

Not to be confused with

Signals are state, not events:

  • DOM events like (click)="handler($event)" or (change) are event streams coming from the user interface, not state containers.
  • RxJS Subject / BehaviorSubject are push-based, asynchronous streams of values. Signals are synchronous, pull-based value cells.

signal, computed and effect all live in @angular/core — no extra dependencies needed. Signals are also what powers Angular's newer functional APIs such as input, output and viewChild.
